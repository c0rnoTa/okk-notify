# Напоминание о перезагрузке ПК

Фоновый PowerShell-агент для ПК хроматографов ОКК. После входа пользователя следит за аптаймом и показывает модальное окно, если компьютер давно не перезагружали.

Благодаря тому, что это не Windows Service процесс стартует **при входе любого пользователя** в **его** интерактивной сессии и может показать окно на рабочем столе. 

## Поведение

Каждые `CheckInterval` (по умолчанию 10 минут) смотрит аптайм системы.

| Аптайм | Что видит пользователь |
| --- | --- |
| меньше `FirstAlertAfter` (7 суток) | ничего |
| от 7 до 8 суток, ещё не нажимал ОК | обычный алерт |
| от 7 до 8 суток, уже нажимал ОК | жёлтый алерт |
| `RedAlertAfter` и больше (8 суток) | красный алерт |

На окне одна кнопка **ОК**. Пока окно открыто, цикл стоит. После ОК агент снова ждёт интервал и проверяет аптайм.

Состояние «уже скликнул обычный алерт» хранится только в памяти процесса. После перезагрузки аптайм обнуляется, и логика начинается заново.

## Установка на весь ПК

Нужны права администратора, один раз на компьютер:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1
```

Скрипт копируется в `%ProgramData%\OKKRebootReminder\` и регистрируется задача планировщика **OKK Reboot Reminder**:

- триггер: вход **любого** пользователя;
- запуск от группы `Users`, без наивысших прав;
- окно рисуется в сессии того, кто вошёл.

Уже открытые сессии агент сам не подхватит — нужен повторный вход или ручной запуск `launch.vbs` из каталога установки.

Свои пороги:

```powershell
.\install.ps1 -CheckInterval 00:10:00 -FirstAlertAfter 7.00:00:00 -RedAlertAfter 8.00:00:00
```

Параметры пишутся в `config.json` рядом со скриптом. Менять их после установки можно правкой этого файла (подхватится при следующем старте агента).

Снятие:

```powershell
.\uninstall.ps1
```

## Установка через Active Directory на конкретный ПК

Ставить нужно политикой **компьютера**, не пользователя: `install.ps1` один раз кладёт файлы в `ProgramData` и регистрирует задачу «при входе любого пользователя».

### 1. Выложить файлы в SYSVOL

В каталог GPO (надёжнее обычной шары — доступен при старте ПК):

`\\<домен>\SYSVOL\<домен>\Policies\{GUID-политики}\Machine\Scripts\Startup\`

Скопировать туда `install.ps1`, `reboot-reminder.ps1` и `launch.vbs`. Через GPMC это тот же каталог, куда попадают скрипты запуска: **Конфигурация компьютера → Политики → Конфигурация Windows → Сценарии → Автозагрузка**.

### 2. Назначить скрипт автозагрузки

В свойствах **Автозагрузка** → **PowerShell Сценарии** (или «Сценарии», если запускаете через `powershell.exe`):

- скрипт: `install.ps1`
- параметры (по желанию): `-CheckInterval 00:10:00 -FirstAlertAfter 7.00:00:00 -RedAlertAfter 8.00:00:00`

Либо действие:

- команда: `powershell.exe`
- аргументы: `-NoProfile -ExecutionPolicy Bypass -File "%~dp0install.ps1"` — в GPMC обычно достаточно `-NoProfile -ExecutionPolicy Bypass -File install.ps1`, рабочий каталог будет каталогом Startup этой GPO.

Скрипт выполняется от **SYSTEM**, этого достаточно для `#Requires -RunAsAdministrator`. Повтор на каждой загрузке безопасен: задача перерегистрируется с `-Force`.

### 3. Ограничить политику одним компьютером

1. Создать GPO, например `OKK Reboot Reminder — <имя ПК>`.
2. Привязать её к OU, где лежит учётная запись этого компьютера (или выше по дереву).
3. На вкладке **Область** у делегирования:
   - у `Authenticated Users` оставить **Чтение**, снять **Применение групповой политики**;
   - добавить объект компьютера `ИМЯПК$` с правами **Чтение** и **Применение групповой политики**.

Без шага 3 политика применится ко всем ПК в OU.

### 4. Применить

На целевом ПК (или после ближайшей перезагрузки):

```powershell
gpupdate /target:computer /force
```

Полития компьютера подхватывается при загрузке. После успешного `install.ps1` в планировщике должна быть задача **OKK Reboot Reminder**, файлы — в `%ProgramData%\OKKRebootReminder\`. Агент в уже открытой сессии появится после выхода/входа пользователя.

Проверка: `gpresult /r` — политика в списке для компьютера; Event Viewer → **Group Policy** / **Task Scheduler**, если задача не создалась.

Снятие с ПК: отдельная GPO со startup-скриптом `uninstall.ps1` (те же файлы в Startup) либо ручной запуск `uninstall.ps1` локально, затем отключить/удалить установочную политику.
